# 项目详情页排版调研：怎样让读者看见做出来的东西

2026-11-17 · Hashflow 博客 · 设计调研

这是第一轮调研，后续采用了[第二轮方案](project-detail-layout-v2-2026-11-18.md)。

**建议先把 Personal Blog 做成一页可以看作品的案例：短简介和体验入口之后，展示工作台从起笔到成稿；往下再用真实过程图、内容管线和发布记录讲清楚怎么做、怎么验证。** 现有页面已经能回答项目是什么、作者负责什么、在哪里上线。最值得调整的是：把代表性成果提前，把资料的权重拉开，让长正文里有几处可以停下来看的东西。

## 调研范围和证据

选了 10 个作者本人发布的单项目详情页或项目复盘。样本覆盖个人技术博客、工程作品集和设计师作品集；标注各自属于哪一种。对比页面第一屏、第一份可见成果、正文如何穿插材料，以及没有界面或演示时怎么展示证据。参考页用一手页面核对，部分用应用内浏览器直接截图。本站查看了线上页面的 1280 × 720 和 390 × 844 两种视口，也核对了仓库源码。适用性、优先级和版式提案是设计判断；没有做用户访谈、转化测试或完整的可访问性审计。

## 改版前的页面：资料齐全，作品本身还没展开

| 阅读步骤            | 实际看到的内容                                                                                                                                  | 改造判断                                                                                                                             |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 1. 进入页面         | 桌面是左侧标题、摘要、黄色结果卡，右侧整张首页缩略图；返回和目录有固定位置。                                                                    | 第一屏能识别项目和已上线的事实。封面缩进了原首页的标题、导航和按钮，工作台只占其中一部分。仅把整张首页截图放大，会一起放大无关信息。 |
| 2. 寻找可以试的东西 | 桌面在首屏下部能看到演示、源码。手机上先读结果、看静态封面，再经过角色、周期和两排标签，向下滚才看到演示。封面下方的操作是查看大图。            | 「在首页试工作台」更具体，也更值得靠近摘要。部署证明与体验入口承担不同任务，两个都值得保留。                                         |
| 3. 继续阅读         | 一列正文、10 个同级二级标题，工作台一节用文字解释绘制、键盘、灯光和叶片；没有内文图片。内容管线、搜索、阅读时间、推荐、SEO、CI 等在目录里同级。 | 工程信息是真实资产。值得选出两三个能说明能力的主题展开，其余做成短说明或链接；把成果和证据放在对应章节。                             |

## 10 个真实案例

### 01 · Ashley Case：先说明做了什么，再给一张宽幅作品图

[Jericho Prince Llagas 的设计作品集详情](https://jerichoprince.work/work/ashley-case/) · [首屏实拍](../../qa-evidence/project-detail-layout-research-2026-11-17/ashley-desktop.jpg)

开头依次是年份与标签、左对齐的大标题、一句介绍客户和作者工作的话、实站与返回项目的按钮；接着跨过正文宽度放一张成品组合图。往下看才出现项目背景、线框图、颜色和字体、原型、上线。结尾的询问和工作机会来自客户反馈转述。

**可借鉴：** 摘要和主操作形成很短的一组，下一块直接给成果。Hashflow 可以用同样顺序，把宽幅位置给工作台局部和短片。素材要能看清单个细节；组合图里的微小界面文字适合营造观感，承担不了细节说明。

### 02 · Portfolio Design System：首图表现结果，正文展示怎样达成

[Ronald Lopez 的个人站重建案例](https://www.ronglopez.com/projects/ronglopez-portfolio.html) · [首屏实拍](../../qa-evidence/project-detail-layout-research-2026-11-17/rong-desktop.jpg)

首屏左侧用大号分行标题、摘要和项目属性定调，右侧把真实站点画面与设计变量界面叠在一起。往下进入九节带编号的目录，旁边提供 Storybook 入口；旧站截图、色阶、对比度例表等材料各自贴着对应的论证。桌面 720 像素高首屏里看不到 Storybook 或完整事实栏。

**可借鉴：** 用真材料建立视觉重点，用图、表或外链分别支持具体结论。有长正文时用分节导航。我们的页面本来就有左右首屏，同样再做一次左文右图，提升主要取决于右边到底展示了什么、左边何时给入口。

### 03 · How I Built My Blog：很早给读者一个可切换的对照

[Josh W. Comeau 的个人博客重建复盘](https://www.joshwcomeau.com/blog/how-i-built-my-blog-v2/) · [正文对照实拍](../../qa-evidence/project-detail-layout-research-2026-11-17/josh-section.jpg)

这是博客文章格式。标题、时间和很短的引入之后就是新旧首页对照，提供切换和放大操作。页面先用外观差异建立共同语境，然后转去讲读者看不见的架构与实现。桌面截图里，完整对照出现在进入正文之后。

**可借鉴：** 一个有对照的问题比一张无说明的封面更好读。本站可以选「结构线 → 线稿 → 成稿」解释实际绘制阶段；如选灯光，则用同一构图展示开关两种状态，并写清它改变了哪里。

### 04 · Datasette Publish：一个用例加一段短录屏，先把项目讲懂

[Simon Willison 的个人技术博客发布页](https://simonwillison.net/2018/jan/17/datasette-publish/)

标题承诺从 CSV 生成在线数据库；开头给了一个具体的竞选财务数据集及产出的实例，紧跟一段演示如何操作的动图，再讲适用人群和技术组合。核对时，文章所链接的旧样例地址已失效，文章的[独立动图](https://static.simonwillison.net/static/2018/datasette-publish-demo.gif)仍能访问。

**可借鉴：** 媒体只演一个动作和响应，读者很快就知道该看什么；现场站点和页面中的记录各有价值。对于本站，可以把一次完整绘制作为主要片段，再把「收笔后可试的交互」写进图注或入口旁。

### 05 · Flexoki：页面本身就在演示成果

[Steph Ango 的个人站项目详情](https://stephango.com/flexoki) · [色板实拍](../../qa-evidence/project-detail-layout-research-2026-11-17/flexoki-section.jpg)

窄栏、纸色背景、三小段介绍；下一节就是可用的调色板。页面用的就是这套配色，顶部开关能展示浅色与深色效果，色块标明可复制。接下来用代码高亮图、设计缘由、色值和移植项目把同一成果讲深。

**可借鉴：** 选择和项目价值直接相关的操作。首屏放「在首页试工作台」，读者已经在作品所在的网站里，知道点过去要做什么；以后如果需要页内互动，也只做一个能展示差异的控件。首版用真实录屏比在详情页再装载整个首页工作台省事。

### 06 · C Compiler：没有界面也能看见系统在做什么

[Ritvik Ellendula 的工程作品集详情](https://ritvikellendula.dev/projects/c-compiler) · [首屏实拍](../../qa-evidence/project-detail-layout-research-2026-11-17/compiler-desktop.jpg)

首屏写明在开发和当前的功能范围，左侧是简述及工程要点，右侧是编译过程图。用同一个 `return ~(-2)` 举例，展示源码怎样经过语法分析、中间表示、汇编，最终变成可检查的结果。正文再展开系统结构、选择和验证。这个页面有较高的信息密度，但配图确实提供了额外信息。

**可借鉴：** 为内容管线选一份真实 Markdown 文件，把实际输入、中间结果和发布产物串起来。后台项目也可以用请求样例、数据流或验证记录做首图。图里只画已实现且可以核实的路径。

### 07 · Crafting the Next.js Website：每个技术细节都配能看懂的局部

[Rauno Freiberg 的个人站 Craft 项目复盘](https://rauno.me/craft/nextjs)

日期和简短开场后进入分节正文，逐个讲栅格线、开关面板、焦点状态等细节。开关一节把视觉反应、原方案遇到的跨浏览器问题、选用的动画方式和代码放在一起。长文可以按感兴趣的细节跳读。

**可借鉴：** 每个精选细节按「看哪里 → 我怎么做 → 为什么这样做」排。工作台可以只讲一个最能说明取舍的局部，例如开灯后亮度变化如何限制在原位置，再附真实对照。没有对应图或交互的小细节可用文字与源码短链。

### 08 · Website Redesign：纯文字也能有辨识度

[Matthew Deutsch 的个人站项目备忘录](https://www.matthewdeutsch.com/projects/website-redesign/) · [首屏实拍](../../qa-evidence/project-detail-layout-research-2026-11-17/memo-desktop.jpg)

用居中的白纸、等宽字、档案号、作者、日期、摘要和编号章节，整体像一份工程备忘录。第一屏没有封面。正文围绕内容、写作流程、外观和技术四个议题展开，版式和主题呼应。

**可借鉴：** 轻素材项目可以用统一的小编号、图注和分隔来建立气质。本站现成的纸色、细线和工作台图稿足够辨认；中文长正文继续使用正文用字，档案感交给小标签和图注承担。

### 09 · 新个人主页介绍：中文项目复盘可以像作者亲自带看

[idealclover 的个人博客项目复盘](https://idealclover.top/archives/643/)

开头先指向新主页并展示页面图、附源码，接着把旧版图放在产生改版需求的段落里。谈适配时跟上不同屏幕布局图，之后再讲字体大小、框架和发布。文章里的 Bento 是被介绍的主页布局，案例页本身按文章顺序读。

**可借鉴：** 用一句作者自己的动机说明「为什么改」，图放在被讨论的位置；有真实桌面、手机差异再并排对比。可从现有绘制调研中提取旧播放方式、改变落笔顺序及其表现，改稿时核对图是否确实来自对应版本。

### 10 · 个人知识库与本地资料检索：保住可核查的工程状态

[Jiayu Lab 的中文工程项目详情](https://www.jiayuhere.com/projects/personal-knowledge-base/index.html)

标题和功能一句话之后，先标出已完成本地验证，再把源码、README、提交记录等入口集中到一起。正文有明确的架构、真实代码摘录、调试与最终效果。无需等候一个公开产品演示才能交代项目。

**可借鉴：** 把「已部署」「仅本地验证」「进行中」写到证据允许的精度。只保留最有用的一两个入口在上方，CI、设计记录与实现入口放相关章节；该页 15 个目录项的详尽程度，更适合存档型案例。

## 本站可选的三种方向

| 方向                     | 页面顺序                                                    | 优势和代价                                                                                                                     | 适用项目                                |
| ------------------------ | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------- |
| **A · 作品先亮相，推荐** | 短简介和入口 → 宽幅作品演示 → 关键细节和证据 → 完整工程说明 | 手机打开就能找得到体验，正文延续博客阅读；需要选取一段真实录屏和一张干净的预览图。参考 Ashley、Josh、Datasette。               | Personal Blog、有可操作成果的工具或页面 |
| **B · 工程过程图打头**   | 解决什么问题 → 一个真实输入走过系统 → 选型取舍 → 测试与结果 | 能把后端系统讲得具体；需要找清楚输入、边界和输出，不能只展示一排技术名。参考 C Compiler、Jiayu Lab。                           | 内容管线、自动化、检索、内部工具        |
| **C · 中文制作手记**     | 为什么做 → 代表性过程图 → 改过哪里 → 现在用得怎样           | 个人味最强，少量素材也成立；读者找成果的速度取决于开头是否简洁，适合把实站入口提前。参考 idealclover、Matthew Deutsch、Rauno。 | 实验、小项目、一次有明确变化的迭代      |

对于这一页，**A 做外层，B 只用于讲内容管线，C 用在作者写取舍的段落。** 优先采用同一套内容顺序，让媒体的大小和数量随项目调整。先不做全页卡片网格、自动轮播或每个项目一种完全独立的模板。这些做法要求更多同级素材，也会打断现有 Markdown 的线性阅读。

## Personal Blog 可以怎么排

1. **标题和体验入口。** 保留 `Personal Blog` 和纸色风格。简介只承担说明用途，例如「一个中文技术博客和作品集，首页用铅笔画出一张可以操作的工作台。」主操作写「在首页试工作台」，次操作写「查看源码」。用小一行写负责范围和已上线状态；部署记录继续可以点。周期和标签随后出现。
2. **宽幅作品舞台。** 选只包含工作台的真实画面做预览，显示「看铅笔绘制 · 约 7 秒」。默认显示成稿，读者主动播放。图注指出从结构线、线稿到阴影和黄色抽屉的变化；手机用实际移动端取景，确保铅笔和关键部件在画面里。图片仍能独立提供信息，并配有文字说明；展示用短片不需要声音或自动循环。
3. **正文保留四个层级清楚的主题。** 「工作台怎样画出来」用少量实拍和一个取舍；「Markdown 怎样变成网站」用具体文件与流程图；「读者怎样找到文章」用一张搜索命中正文的真实界面；「怎样验证并发布」用导出的页面、部署记录和已做过的检查。推荐、阅读时间和 SEO 按主题合并为简短说明，具体实现留链接。长正文沿用目录和正文阅读宽度，宽幅媒体只占需要看细节的几处。
4. **结尾给当前案例的下一步。** 可以到首页体会、看工作台设计记录或查发布流程；只有确实有其他项目时才放「下一个项目」。技术标签为补充，不替代真实结果，也不把文章数量当成使用成效。

素材基础：[工作台的约 6.6 秒分镜与取舍](./workbench-build-drawing-2026-11-17.md)、[现有桌面录屏](../../qa-evidence/workbench-build-v2/desktop.webm)、[现有窄屏录屏](../../qa-evidence/workbench-build-v2/mobile.webm)、[Content Catalog 实现](../../src/lib/content-catalog.ts)、[GitHub Pages 发布流程](../../.github/workflows/deploy.yml)。QA 录屏用作选材：本机桌面 WebM 约 2.4 MB，对应 GIF 约 7 MB，正式使用前再裁剪并编码。流程图应从同一份内容快照分出各消费者，不能画成「详情页生成 RSS」。如果最初只发静态图，Markdown 已支持图片，项目正文继续用现有编译流程；如果加短视频，单独处理媒体和文本回退，沿用静态导出的资源路径。

首轮评审看三个问题：**手机打开能否直接找到体验入口？不打开外部链接，能否看懂工作台最有意思的动作？继续往下，能否从至少一份真实材料看懂一项技术取舍？** 建议先用现有素材完成首屏和「工作台怎样画出来」一节的样稿，再决定要不要为后续项目抽象模板。
