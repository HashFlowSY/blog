# 博客 Markdown 渲染的开源方案

这是迁移前的调研记录；旧代码路径对应提交 `43fe480`，新实现和验证见[验收记录](../../.scratch/shiki-markdown-migration/acceptance.md)。

建议采用 **`@shikijs/rehype` + 官方行高亮 transformer + 站点自己的中文复制按钮**。Shiki 可替换 手写分行（`src/lib/rehype-code-block.ts`），文章和项目案例可以共用一个正文组件。临时静态样例验证了它能标对跨行注释并保留代码空白。若更看重内置终端框、文件名和复制按钮，`rehype-expressive-code` 是功能更完整的备选，但要处理空白裁剪和 Next.js 站内跳转。两者都能接入现有 Markdown 管线（`src/lib/markdown.ts：315`），保留普通 `.md`、YAML 和正文、目录、搜索共用一棵树的做法。 [Shiki Rehype](https://shiki.style/packages/rehype) · [Expressive Code 功能](https://expressive-code.com/key-features/frames/) · [前次调研](markdown-rendering.md)

## 静态样例实测

2026-11-13，在独立临时项目中使用 Node.js 24.22.2 和 Next.js 16.4.3，设置 `output: "export"`、`basePath: "/blog"`。三种代码块插件分别处理同一份 Markdown：`remark-gfm` → `remark-rehype` → `rehype-sanitize` → 候选插件 → `rehype-stringify`。正文仍以 HTML 字符串传给 React，模拟当前博客的显示方式。三个候选都完成了静态构建；Chrome 关闭 JavaScript 后，代码和高亮行标记仍在页面里。Shiki 和 Pretty Code 的行背景仍需站点 CSS。

| 样例                                                  | Shiki                                          | Rehype Pretty Code                                        | Expressive Code                                                            |
| ----------------------------------------------------- | ---------------------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------- |
| `ts {2}`：三行代码，块注释跨第 1、2 行                | 正确标记第 2 行 ` * second */`                 | 同左                                                      | 同左                                                                       |
| `ts {2}`：首尾各一个空行，中间包含 Tab 和两个行尾空格 | 保留三行，代码文本与解析后的围栏原文相同       | 保留三行，但在空行中补了一个空格                          | 裁成一行，行尾空格被去掉，`{2}` 不再匹配；设置 `tabWidth: 0` 后 Tab 仍保留 |
| 未知语言及未标注语言                                  | 显式设置回退后，均输出纯文本；未知语言仍可标行 | 未知语言可显示并标行；未标注的围栏默认沿用普通 `pre/code` | 两者都可显示；未知语言产生构建日志并回退到 `txt`                           |

另在 Chrome 中观察复制按钮实际传给剪贴板接口的值。Expressive Code 的默认内联脚本在直达详情页时工作；从无代码块的首页经 `next/link` 首次进入时，页面未整页重载，按钮没有调用剪贴板。通过 `customCreateRenderer` 将 `jsModules` 从正文移出，用独立的 `next/script` 加载后，站内进入时也能复制。这个验证使用剪贴板替身观察调用，没有检查真实系统剪贴板权限。Shiki 和 Pretty Code 主包不提供复制按钮，这次没有给它们接入新的复制组件。

### Expressive Code 接入现有正文

- **静态样式和复制脚本。** 普通 `.md` 的 rehype 插件默认把 CSS 和 `<script type="module">` 放进代码块的 HTML。静态首屏由浏览器解析，站内切页经 React 的 HTML 注入时，片段里的脚本不会执行。接入时可复用 `createRenderer` / `customCreateRenderer`，将 `baseStyles`、`themeStyles` 放到页面级样式，通过 `next/script` 加载 `jsModules`，让插件保留代码块专用样式。Core 对应的 API 是 `getBaseStyles`、`getThemeStyles`、`getJsModules`，CSS 和 JS 由调用方加载。复制模块会初始化已有按钮，也会观察新增节点。禁用 JavaScript 时配色和行标记仍可阅读，Frames 样式会隐藏复制按钮。若发布独立资源文件，其 URL 需要使用站点的 `basePath`。 [插件的资源注入](https://github.com/expressive-code/expressive-code/blob/rehype-expressive-code@0.44.3/packages/rehype-expressive-code/src/index.ts#L131-L243) · [HTML 脚本规范](https://html.spec.whatwg.org/multipage/scripting.html#the-script-element) · [Next.js Script](https://nextjs.org/docs/app/api-reference/components/script#afterinteractive) · [复制脚本](https://github.com/expressive-code/expressive-code/blob/rehype-expressive-code@0.44.3/packages/@expressive-code/plugin-frames/src/copy-js-module.ts#L94-L118) · [无 JavaScript 样式](https://github.com/expressive-code/expressive-code/blob/rehype-expressive-code@0.44.3/packages/@expressive-code/plugin-frames/src/styles.ts#L413-L447) · [站点路径](../../src/lib/site.ts)
- **复制原文和行号。** Expressive Code 会去掉每行末尾的空白以及代码首尾的空行，行标记因此可能错位。`tabWidth: 0` 可保留 Tab，关闭文件名提取和终端注释过滤可保留对应注释。内置按钮把处理后的 `codeBlock.code` 写入 `data-code`，剪贴板拒绝时尝试回退复制，两种方式均失败时没有反馈。若复制必须与围栏原文一致，使用高亮前的 `mdast.code.value` 作为复制来源，并校验显示行号。 [Tab 处理](https://github.com/expressive-code/expressive-code/blob/rehype-expressive-code@0.44.3/packages/rehype-expressive-code/src/index.ts#L277-L289) · [空白处理](https://github.com/expressive-code/expressive-code/blob/rehype-expressive-code@0.44.3/packages/@expressive-code/core/src/common/block.ts#L139-L151) · [文件名提取](https://github.com/expressive-code/expressive-code/blob/rehype-expressive-code@0.44.3/packages/@expressive-code/plugin-frames/src/utils.ts#L172-L216) · [剪贴板源码](https://github.com/expressive-code/expressive-code/blob/rehype-expressive-code@0.44.3/packages/@expressive-code/plugin-frames/src/copy-js-module.ts#L47-L72)

## 正文和整站方案

- **标题自链接。** MIT 的 `rehype-autolink-headings` 可以用最终标题 ID 生成自链接。放在净化和目录提取之后可复用 `user-content-…` 这类已有 ID，并用 `test` 跳过脚注标题。默认的前置或后置链接对键盘和辅助技术隐藏，若链接要供读者操作，需配置可聚焦且有中文名称的链接。正文中作者写的 `#标题`、脚注的双向引用和 `/blog` 下的链接及图片地址仍由站点按自己的 ID 和路径规则处理。 [MIT](https://github.com/rehypejs/rehype-autolink-headings/blob/7.1.0/license) · [插件选项](https://github.com/rehypejs/rehype-autolink-headings#options) · [脚注选项](https://github.com/remarkjs/remark-rehype#example-footnotes-in-languages-other-than-english) · [净化的 ID 前缀](https://github.com/rehypejs/rehype-sanitize#example-headings-dom-clobbering) · [站点路径](../../src/lib/site.ts)
- **YAML frontmatter。** MIT 的 `vfile-matter` 5.0.1 可在内容目录读取文件后直接用。`matter(file, { strip: true })` 只识别起始 `---` 围栏，用 `yaml` 解析并移除 frontmatter，没有 gray-matter 的语言引擎选择。现有 Zod 校验负责缺失或无效的元数据。`remark-frontmatter` 适合把围栏识别放到 Markdown AST 中，它只识别语法，仍需 YAML 解析器。 [vfile-matter MIT](https://github.com/vfile/vfile-matter/blob/5.0.1/license) · [解析源码](https://github.com/vfile/vfile-matter/blob/5.0.1/lib/index.js#L35-L79) · [remark-frontmatter 用法](https://github.com/remarkjs/remark-frontmatter#example-frontmatter-as-metadata) · [内容目录](../../src/lib/content-catalog.ts#L173)
- **正文排版。** MIT 的 `@tailwindcss/typography` 给渲染后 HTML 提供 `prose` 样式和颜色变量，支持现用的 Tailwind CSS v4。可参考它的字号、行距和暗色变量，评估直接替换时要核对现有 `.prose`、中文字体和表格对齐。`github-markdown-css` 也是 MIT，适合希望整块正文采用 GitHub 排版时使用。 [Tailwind Typography MIT](https://github.com/tailwindlabs/tailwindcss-typography/blob/main/LICENSE) · [Tailwind Typography 用法](https://github.com/tailwindlabs/tailwindcss-typography#installation) · [github-markdown-css](https://github.com/sindresorhus/github-markdown-css#usage) · [现有正文 CSS](../../src/app/globals.css#L496)
- **`@uiw/react-markdown-preview` 5.2.1。** MIT 的完整 React 正文组件，内置 GitHub 风格、GFM、Prism 高亮和复制。它把 Markdown 源文交给 `react-markdown` 解析，默认 URL 转换原样返回。接入时要把现有净化、目录及搜索提取迁入该流程，才可复用同一棵树。 [MIT](https://github.com/uiwjs/react-markdown-preview/blob/v5.2.1/LICENSE) · [默认 rehype 插件](https://github.com/uiwjs/react-markdown-preview/blob/v5.2.1/core/src/index.tsx#L15-L26) · [组件源码](https://github.com/uiwjs/react-markdown-preview/blob/v5.2.1/core/src/preview.tsx#L11-L60)
- **Nextra 4.6.1。** MIT 的 Next.js 博客主题支持 `.md` / `.mdx` 和静态导出。其编译器已用 `rehype-pretty-code`，用 React 组件实现复制，用 Pagefind 构建搜索。适合需要整套主题、文件路由与搜索时考虑。迁移当前站点要重新接合文章与项目的内容契约、显式 `slug`、目录和搜索，借鉴它的代码块实现成本更低。 [MIT](https://github.com/shuding/nextra/blob/nextra@4.6.1/LICENSE) · [编译器](https://github.com/shuding/nextra/blob/nextra@4.6.1/packages/nextra/src/server/compile.ts#L94-L109) · [高亮接入](https://github.com/shuding/nextra/blob/nextra@4.6.1/packages/nextra/src/server/compile.ts#L199-L221) · [复制组件](https://github.com/shuding/nextra/blob/nextra@4.6.1/packages/nextra/src/client/mdx-components/pre/copy-to-clipboard.tsx) · [静态导出和 Pagefind](https://nextra.site/docs/guide/static-exports) · [稳定 slug 约定](../adr/0003-use-explicit-stable-slugs.md)

## 接入边界

1. **复用插件，保留站点规则。** 保留现有 HTML 净化。在同一棵树上确定最终 ID、处理脚注和站内路径并提取目录与搜索，再运行受信任的高亮插件。现有 `remark-rehype` 已把围栏元信息放入 `code.data.meta`，净化会保留该字段，接入后可移除 手写元信息插件（`src/lib/remark-code-meta.ts`）。给插件前先验证 `{1,3-5}` 的数字和范围，按实际行数限制上界，避免库按任意范围展开。 [净化与高亮顺序](https://github.com/rehypejs/rehype-sanitize#example-syntax-highlighting) · [围栏元信息](https://github.com/syntax-tree/mdast-util-to-hast/blob/13.2.1/lib/handlers/code.js#L17-L39) · [净化保留节点数据](https://github.com/syntax-tree/hast-util-sanitize/blob/5.0.2/lib/index.js#L725-L735) · [Shiki 区间解析](https://github.com/shikijs/shiki/blob/v4.6.0/packages/transformers/src/transformers/meta-highlight.ts#L3-L20)
2. **收拢正文和复制。** 两类详情页共用正文组件；代码背景、行标记和键盘焦点沿用站点样式。复制和搜索都以语义文本为准，复制保留围栏内容的空白并反馈成功或失败。Expressive Code 的 `code.textContent` 会把相邻的行直接拼接，不能用作复制原文或搜索索引的输入。
3. **验收正式接入。** 用含脚注、已有标题锚点、站内图片、多行注释、空行、缩进和未知语言的样例，核对 `/` 和 `/blog` 导出的直达、站内切页、无 JavaScript 阅读与复制原文。以上实测仅覆盖独立静态样例，没有把第三方依赖接入博客，也没有评估整站体积和构建耗时。 [静态产物验收约定](../adr/0002-test-the-deployable-static-artifact.md)
