# 首页工作台：从定位到成稿的手绘动画

2026-11-17 · 调研与实现提案

本文对应 11 月 17 日提交的逐笔版本。当前分镜和验收见[首页二维工作台](../design/workbench-interaction-design.md)。

建议让整个工作台一起从浅到深成形。先用点和结构线定出台面、桌脚和挂板的位置，再画出有厚度的台面和柜体，让电脑、凳子和工具有地方可以摆放。草稿确定后，沿原来的结构压出更深的轮廓，再画明暗、材质和黄色抽屉。**Build 的感觉来自后一笔接住前一笔：能看出这个面是由哪些边围成的，哪个部件由什么支撑，阴影落在哪里。**

## 改造前的画面与原因

改造前先放完整画稿，再用纸面遮住未完成区。铅笔沿遮罩开出缝隙，一起露出成稿的轮廓、纹理和阴影。六个区域大致从上往下画，用于显影的排线宽 52 个图稿坐标单位、间隔 19，设计上重叠填满各区域。一处已有成稿细节，其他地方仍缺少主体轮廓。定位点占约 0.69 秒，随后一起退淡。 [原渲染层](https://github.com/HashFlowSY/blog/blob/5375fab974d5e50cc304ad0a9fa2073fbd7bbdfc/src/components/home/workbench-drawing.tsx#L60) · [原六区数据](https://github.com/HashFlowSY/blog/blob/5375fab974d5e50cc304ad0a9fa2073fbd7bbdfc/src/components/home/workbench-geometry.ts#L151) · [原时序](https://github.com/HashFlowSY/blog/blob/5375fab974d5e50cc304ad0a9fa2073fbd7bbdfc/src/components/home/pencil-plan.ts#L66)

## 播放分镜与落笔顺序

全程约 6.6 秒。开场的点和线沿一条可追踪的路线出现，笔尖从右桌脚上行到台面，沿台面从右向左，接到挂板左上方，再画搁板。定位点在笔尖触纸时出现。笔尖经过的线保留在纸上，到后续压线时才局部退淡。同一时刻只有一处接触。

| 阶段     | 时间         | 笔触顺序和这一段结束时的画面                                                                                                         |
| -------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 点、线   | 0–1.25 秒    | 右桌脚的浅记号紧接向上的支撑线。台沿从右向左画，再接到挂板左上方和搁板。每一笔从笔尖经过处长出，能一路追踪到上方的结构。             |
| 面、草稿 | 1.25–2.65 秒 | 从已画的台沿连出进深和厚度，接出柜侧。相应结构边线完成后再上浅调子。用薄盒形画电脑和显示器，用椭圆画凳座和盆口，再勾出挂具的浅轮廓。 |
| 线稿     | 2.65–3.85 秒 | 沿草稿压深台沿、桌腿和柜体主边，再描屏框、抽屉缝、工具结构和搁板底边。被遮挡和被替换的草线按部件退淡。                               |
| 阴影     | 3.85–5.35 秒 | 画搁板下、台面下和柜侧的暗部，再在桌脚与凳脚接地处压深。短排线沿木面、柜侧和地面各自的方向展开，同时补齐挂孔与挂具细节。             |
| 成片     | 5.35–6.45 秒 | 先画笔记本和显示器里的小图，再沿抽屉面分三笔铺黄，最后补台沿高光。各处纹理随相关笔画补齐。到段末画面已与原稿对齐。                   |
| 抬笔     | 6.45–6.6 秒  | 铅笔抬离画纸，画稿保持稳定。铅笔离场且部件素材就绪后开放互动。                                                                       |

保留能看清笔尖的连线、压线和排线。挂板孔、木纹和螺丝可以各跟随自己所在部位的相关动作。在本阶段未触及的部位保留纸面及已有笔画。

## 素材怎么制作

1. **统一坐标。** 仓库里的 [纸稿](https://github.com/HashFlowSY/blog/blob/c57ab05f6eaa4ce5ee6e0a5090bfba1a26437660/public/assets/workbench-2d/workbench-paper.webp)和[成稿](../../public/assets/workbench-2d/workbench-rest.webp)是同为 `1440 × 900` 的不透明 WebP。以成稿叠图定位，继续使用 `viewBox="0 82 1440 682"`。手机横向取景约为原图 `x=570–1340`，先检查所有阶段的重点是否落在这个范围内。桌沿前角、桌腿与地面接触点、柜侧、屏框下缘等交界，应在草稿、线稿、光影及原稿之间逐一对齐。[坐标和热点](https://github.com/HashFlowSY/blog/blob/c57ab05f6eaa4ce5ee6e0a5090bfba1a26437660/src/components/home/workbench-art.ts#L16) · [当前手机裁切](https://github.com/HashFlowSY/blog/blob/c57ab05f6eaa4ce5ee6e0a5090bfba1a26437660/src/components/home/assembly-workbench.module.css#L61)
2. **按叠放关系画中间素材。** 以现有纸稿为底，画浅结构、草稿、净线和短排线，分别存成 SVG 路径数据。台面底调和阴影分别裁到各自表面，净线仍位于其上。工作台后方的草线在显示器、工具等物体的覆盖范围内渐退。给确信的前缘用较深、较重的笔触，给次要接缝和辅助线留较浅的石墨色。以首页实际尺寸确定线宽和对比度，尤其确认手机上的细线在抗锯齿后仍能看清。
3. **先定光影形状，再加质感。** 手工标出台面下缘、柜侧和桌脚接触处的阴影边界。主排线用真实短线呈现，接触处更密，向外逐渐稀疏。黄色抽屉在上色前已有明确的柜面、抽屉缝和暗边。把木纹、挂孔、屏幕细纹等高频内容对应到各自的小范围，供收尾时对版。
4. **先验最关键的几笔。** 用从右桌脚到搁板的整条路线确认开场在手机上可读。用右桌脚、柜面、地面投影和黄抽屉确认局部调子与原稿如何对齐，再检查上半部和小物件。用关键帧核对叠放，用桌面和手机录屏看连续画面。

从同一张 `workbench-rest.webp` 取局部纹理。各处对应的笔画先画出轮廓、调子或颜色，纹理随后叠到同处。台沿、抽屉和地面接触影各自使用与形状相合的局部范围。超出物体的浅结构线在相关笔画完成后单独退淡。纸色由同一纸面承接。

把原稿中的每处差异分配给相关动作。地面浅线和边缘纸纹也属于图稿内容，安排在画到相应位置后完成。到 6.45 秒完成各处对版，成稿在抬笔前已经准确。抬笔期间纸面和整幅画稿保持逐像素稳定，结束时使用同一坐标的原稿节点。用真实 Chromium 和 WebKit 的连续帧核对接缝及画面边缘。

等待和失败行为约定如下。

- 等待画纸或成稿时，显示同一尺寸的静止纸底。预加载顺序和水合的快慢都不应让成稿提前闪出来。参考线可以用少量内联图形，首屏加载无需额外的占位大图。
- 开启减少动态效果时，加载完成便显示成稿，跳过开场动画素材的请求。纸稿失败时同样显示可用成稿。铅笔图失败可隐藏笔身和接触点，实际笔触继续播放。
- 成稿失败时显示现有读屏提示，热点不出现。部件素材失败时画面留在成稿，继续使用现有交互就绪规则。新增资源沿用 `assetPath`，以部署前缀 `/blog` 验证。
- 等待中切到后台，回到前台且进入视口后开始。绘制中切到后台，直接收笔。浏览器历史缓存恢复时重置画稿进度和交互状态，重新满足视口条件再播放。

## 验收标准

以实际首页为验收环境。桌面用 `1440 × 900`，手机用 `390 × 844`，在 Chromium 和 WebKit 检查。计时从工作台可见且播放开始算起。先以正常速度看一遍，再用确定性时钟取首个落点、台沿、挂板、搁板、各阶段末尾的关键帧，以及最后 `0.25` 秒的逐帧图。

| 正常收笔           | Linux Chromium 使用 `1440 × 900`、DPR 1，从页面坐标 `(618, 91)` 取 `720 × 607` 成稿选区。部件归位后和现有概念图比对，**RGB 差异像素为 0**。收笔后停止播放时钟。 [现有成稿基线](../../design-qa.md#2026-11-15-首页二维工作台验收) · [像素测试](https://github.com/HashFlowSY/blog/blob/c57ab05f6eaa4ce5ee6e0a5090bfba1a26437660/e2e/visual-regression.spec.ts) |

| 减少动态效果与失败 | 加载前开启减少动态效果时，成稿就绪后直接显示，纸稿与铅笔素材没有网络请求。纸稿单独失败时直接显示可用成稿。铅笔单独失败时笔触继续播放，画面上没有残留笔身或接触点。成稿失败时有读屏提示且热点不可用。部件图失败时保留成稿和现有不可操作提示。                                                                                                                  |

| 静态产物           | 使用实际 `out/` 产物及 `/blog` 部署前缀运行现有检查。验收覆盖类型检查、lint、单元测试、Chromium、WebKit、无障碍与 Linux 视觉基线。 [静态产物验证](../static-verification.md)                                                                                                                                                                                  |
