# Shiki 整体替换技术调研

这是迁移前的调研记录；旧代码路径对应提交 `43fe480`，新实现和验证见[验收记录](../../.scratch/shiki-markdown-migration/acceptance.md)。

建议用 `unified` 解析普通 Markdown 和 GFM，用 `rehype-sanitize` 净化 HTML 语法树（HAST），用 Shiki 4.6.0 的 `codeToHast` 生成代码块，再用 `hast-util-to-jsx-runtime` 2.3.6 在 Next.js 服务端渲染正文。文章和项目案例共用正文组件，中文复制按钮是客户端组件。Shiki 4.6.0 要求 Node.js ≥20，仓库使用 Node.js 24。本次的 Next.js 16.4.3 隔离样例验证了服务端正文、高亮、表格对齐和客户端复制。完整切换的行为与验收范围见实施规格。 [Shiki 的 Next.js 组件示例](https://shiki.style/packages/next#custom-components) · [Shiki 的 Node 版本要求](https://github.com/shikijs/shiki/blob/v4.6.0/packages/shiki/package.json#L47-L49) · [仓库版本](../../package.json) · [实施规格](../../.scratch/shiki-markdown-migration/spec.md) · [前次静态样例](markdown-open-source.md#静态样例实测)

## 候选方案

- **直接调用 Shiki，HAST 转 JSX。** 站点从 Markdown 节点取得代码原文和围栏元信息，在高亮前校验语言及行号。Shiki 返回 `Root`，取 `structure: "classic"` 生成的 `<pre>` 元素替换原节点。这样可以在同一棵树上提取目录和搜索，再用 React 组件渲染语言标签和复制按钮。站点仍需定义锚点、搜索分块、代码块 CSS 和复制状态。 [Shiki 输出结构](https://github.com/shikijs/shiki/blob/v4.6.0/packages/core/src/highlight/code-to-hast.ts#L96-L135) · [逐行渲染和最终节点](https://github.com/shikijs/shiki/blob/v4.6.0/packages/core/src/highlight/code-to-hast.ts#L164-L230)
- **`@shikijs/rehype` 加 HTML 序列化。** 官方插件会从 `language-*`、`code.data.meta` 和文本节点取值，默认去掉转换器附加的一个行尾换行。4.6.0 的完整入口默认加载所有打包语言，未命中语言且未启用延迟加载或指定回退时会静默保留原 `<pre>`。直接用插件需要另加输入校验和源码传递。若整篇正文输出 HTML 字符串，React 复制按钮还需要另设挂载位置或先把正文拆成片段。 [插件初始化](https://github.com/shikijs/shiki/blob/v4.6.0/packages/rehype/src/index.ts#L24-L44) · [围栏读取](https://github.com/shikijs/shiki/blob/v4.6.0/packages/rehype/src/handlers.ts#L34-L59) · [语言选择和替换](https://github.com/shikijs/shiki/blob/v4.6.0/packages/rehype/src/core.ts#L67-L140)
- **Pretty Code 或 Expressive Code。** `rehype-pretty-code` 0.14.6 提供行号、词级高亮、标题和题注，其代码块实现捕获高亮失败后会改用 `plaintext`。Expressive Code 0.44.3 提供代码框、主题和复制脚本，构造代码块时会裁去行尾空白及首尾空行，默认把所需脚本插入正文，站内导航需单独处理资源加载。这些现成能力适用于想采用其编辑语法和代码框的项目。本次按作者原文定位行号及复制，直接调用 Shiki 可以少引入一层代码块规则。 [Pretty Code 围栏渲染](https://github.com/rehype-pretty/rehype-pretty-code/blob/rehype-pretty-code@0.14.6/packages/core/src/index.ts#L345-L418) · [Expressive Code 空白处理](https://github.com/expressive-code/expressive-code/blob/rehype-expressive-code@0.44.3/packages/@expressive-code/core/src/common/block.ts#L129-L148) · [资源插入](https://github.com/expressive-code/expressive-code/blob/rehype-expressive-code@0.44.3/packages/rehype-expressive-code/src/index.ts#L173-L229)
- **`react-markdown` 或 MDX。** `react-markdown` 的 `MarkdownAsync` 适合接收 Markdown 字符串并在组件内运行异步插件，组件内部同样调用 JSX 转换器。当前内容目录在渲染页面前就要生成搜索文本及目录，接入这个入口会把提取搬入它的内部管线，或再解析一遍正文。`@next/mdx` 的优势是作者能在正文写 JSX 和导入组件，采用 App Router 要设置 `mdx-components.tsx`，YAML frontmatter 仍需额外处理。本次需要的组件由站点决定，直接渲染类型化 HAST 即可。 [react-markdown 10.1.0 源码](https://github.com/remarkjs/react-markdown/blob/10.1.0/lib/index.js) · [Next.js 16.4.3 MDX 指南](https://github.com/vercel/next.js/blob/v16.4.3/docs/01-app/02-guides/mdx.mdx)

## 编译与渲染边界

1. 内容目录用 `vfile-matter` 5.0.1 读取文首 `---` 之间的 YAML，将 `file.data.matter` 交给现有内容契约。`strip: true` 可直接给正文编译器提供剥离 frontmatter 的文本，报错行号要加上剥离的行数才能定位到源文件。VFile 的字节输入由 `TextDecoder` 读取，处理 UTF-8 BOM。输入由 `remark-parse` 和 `remark-gfm` 解析一次，`remark-rehype` 转成 HAST，使用 unified 的 `parse` 和 `run` 得到语法树。 [vfile-matter 的封套和 strip 实现](https://github.com/vfile/vfile-matter/blob/5.0.1/lib/index.js#L32-L74) · [VFile 解码](https://github.com/vfile/vfile/blob/6.0.3/lib/index.js#L564-L575) · [unified 的运行阶段](https://github.com/unifiedjs/unified/blob/11.0.5/readme.md#processorruntree-file-done) · [内容目录约定](../adr/0005-build-an-atomic-content-catalog.md)
2. `remark-rehype` 按默认规则丢弃原始 HTML，`rehype-sanitize` 执行元素、属性和 URL 协议检查。净化后只运行由仓库控制的变换，包括片段绑定、文章结构提取及 Shiki。Shiki 的 `style` 由固定主题生成，净化 schema 只需支持 Markdown 输出的语义属性。Shiki 会把 `meta` 中名称不以下划线开头的字段写入 `<pre>` 属性，站点应把校验后的围栏元信息放入 HAST `data`。 [原始 HTML 的转换规则](https://github.com/syntax-tree/mdast-util-to-hast/blob/13.2.1/lib/handlers/html.js#L17-L26) · [净化和高亮顺序](https://github.com/rehypejs/rehype-sanitize/blob/6.0.0/readme.md#example-syntax-highlighting) · [Shiki 的 meta 和 data](https://github.com/shikijs/shiki/blob/v4.6.0/packages/core/src/highlight/code-to-hast.ts#L115-L135)
3. 净化并确定最终锚点后、加入高亮和按钮前，从同一棵树提取 H1–H3 目录、文章搜索文本及阅读统计。搜索沿用段落、标题、列表项、表格行和代码块的分块语义，代码块取原始代码，脚注索引定义正文并跳过引用序号、返回标记与隐藏标签。阅读统计跳过块级代码，口径见下节。搜索索引路由只消费编译结果中的文本块，不需要把正文再次转换成 React。 当前分块规则（`src/lib/markdown.ts：221`） · [索引路由](../../src/app/search-index.json/route.ts)
4. 正文在 Next.js 16.4.3 的服务端组件调用 `toJsxRuntime`，传入 `react/jsx-runtime` 的 `Fragment`、`jsx`、`jsxs` 和 `components: { pre: … }`，设置 `passNode: true`。映射接收转换好的 `children` 与可选的原 HAST `node`。由服务端组件从 `node.data` 读代码记录，将转换后的 `className`、`style`、`tabIndex` 和子树透传给真实 `<pre>`，将 `node` 留在服务端。只映射 `pre` 可独立处理块级代码，行内 `<code>` 仍由普通正文样式控制。转换器会默认按同级标签及序号生成 React key，通过运行时第三个参数传入。表格结构中的纯空白文本会被移除，`td`、`th` 的 `align` 默认转为 `style.textAlign`。 [映射和子节点](https://github.com/syntax-tree/hast-util-to-jsx-runtime/blob/2.3.6/lib/index.js#L159-L186) · [传入 node 和创建元素](https://github.com/syntax-tree/hast-util-to-jsx-runtime/blob/2.3.6/lib/index.js#L316-L359) · [表格对齐](https://github.com/syntax-tree/hast-util-to-jsx-runtime/blob/2.3.6/lib/index.js#L400-L434) · [key 和 React 属性转换](https://github.com/syntax-tree/hast-util-to-jsx-runtime/blob/2.3.6/lib/index.js#L503-L582)
5. 复制按钮只接收源码字符串。点击时调用 `navigator.clipboard.writeText`，根据结果给出中文提示，并保留键盘操作与辅助技术播报。构建时生成正文 HTML 和供站内导航使用的 RSC 数据，复制组件在浏览器接管按钮。实施时测量同一代码样例的 HTML 和 RSC 数据体积，尤其是源码既呈现在代码节点中又传给复制按钮的影响。 [Next.js 16.4.3 静态导出](https://github.com/vercel/next.js/blob/v16.4.3/docs/01-app/02-guides/static-exports.mdx#L41-L50) · [服务端与客户端数据边界](https://github.com/vercel/next.js/blob/v16.4.3/docs/01-app/02-guides/server-and-client-boundary.mdx#L130-L168) · [剪贴板写入规范](https://www.w3.org/TR/clipboard-apis/#dom-clipboard-writetext) · [ARIA status](https://www.w3.org/TR/wai-aria-1.2/#status)

React 19 把 JSX 类型放在 `React.JSX`，而转换器 2.3.6 的通用声明仍引用全局 `JSX`。站点可给 `pre` 映射显式标注 `ComponentPropsWithoutRef<"pre"> & { node?: Element | undefined }`，在服务端转换入口标注 React 的返回类型。 [转换器类型声明](https://github.com/syntax-tree/hast-util-to-jsx-runtime/blob/2.3.6/lib/types.d.ts#L119-L153) · [React 19 JSX 类型](https://react.dev/blog/2024/04/25/react-19-upgrade-guide#the-jsx-namespace-in-typescript)

## 正文字词数与预计阅读时长

现有内容目录把剥去 frontmatter 的原始 Markdown 交给估算器，代码和链接地址等源文内容也可能计入。建议在同一次 Markdown 编译中，从净化、移除重复首标题后的 HAST 提取阅读统计，再运行 Shiki。取标题、段落、列表、引用、表格、链接文字、行内代码和已渲染的脚注定义正文。跳过 `<pre>`、脚注引用序号、回链和生成的脚注标题。只读文本节点，链接地址及图片替代文字等属性不参与计数。块、表格单元格及 `<br>` 形成词边界，强调或链接拆开的连续行内文字按显示内容拼接。上游给脚注引用和回链生成了独立标记，同一定义由脚注区渲染一次。 [当前目录调用](../../src/lib/content-catalog.ts#L238) · [脚注引用标记](https://github.com/syntax-tree/mdast-util-to-hast/blob/13.2.1/lib/handlers/footnote-reference.js#L26-L67) · [脚注定义和控件](https://github.com/syntax-tree/mdast-util-to-hast/blob/13.2.1/lib/footer.js#L123-L238)

## 代码内容与构建行为

- **原文。** `mdast-util-to-hast` 13.2.1 的默认 handler 为非空代码文本补一个 `\n`，并将围栏元信息存到 `<code>.data.meta`。新 handler 可直接把 `mdast.code.value`、语言、校验后的行范围与位置放到 `<pre>.data`，净化器会克隆该字段。高亮与行数使用同一个换行规范化后的文本，把 CRLF 或单独的 CR 转为 LF。复制使用原始 `code.value`，保留其中的空行、Tab 和行尾空格。CommonMark 的容器缩进已在解析阶段处理，系统剪贴板可按平台调整换行。 [Markdown 代码节点解析](https://github.com/syntax-tree/mdast-util-from-markdown/blob/2.0.3/dev/lib/index.js#L556-L608) · [默认 HAST handler](https://github.com/syntax-tree/mdast-util-to-hast/blob/13.2.1/lib/handlers/code.js#L16-L44) · [净化器克隆数据](https://github.com/syntax-tree/hast-util-sanitize/blob/5.0.2/lib/index.js#L721-L735) · [Shiki 换行处理](https://github.com/shikijs/shiki/blob/v4.6.0/packages/primitive/src/utils/strings.ts#L16-L38)
- **语言。** 使用 Shiki 全包的正式语言 ID 和官方别名，以 `Object.hasOwn(bundledLanguages, lang)` 检查打包语言。围栏省略语言和缩进代码是 CommonMark 的合法语法，站点可定义其语言为 Shiki `text`，显式 `text` 同样走这一条管线。纯文本也可以用 `text {2}` 标出指定行。未知显式标签使构建失败，报出文件、起始行和标签。Shiki 的纯文本模式也生成逐行结构，`ansi` 是单独处理终端转义序列的模式。 [CommonMark 围栏](https://spec.commonmark.org/0.31.2/#fenced-code-blocks) · [Shiki 全包语言与别名](https://github.com/shikijs/shiki/blob/v4.6.0/packages/shiki/src/langs-bundle-full.ts#L1825-L1828) · [Shiki 纯文本和 ANSI](https://shiki.style/languages#special-languages)
- **行高亮。** 围栏支持完整的 `{1,3-5}` 格式，按 1 起算。先检查整个元信息和每个十进制整数，要求安全整数及 `1 ≤ 起点 ≤ 终点 ≤ 实际行数`，校验完成后才做展开或合并。Shiki 4.6.0 的官方 `transformerMetaHighlight` 会按输入区间直接分配数组，因此新管线应把已验证的行号或区间交给 `line` 钩子，由钩子在 Shiki 生成的行元素上添加样式标记。空代码也会得到一个 Shiki 行节点，作者可标记的行数应按正文规范定义。Shiki 在行元素间插入换行文本，CSS 需要实测空行高度和整行背景，保证样式层的行距与原文行数一致。 [官方元信息解析](https://github.com/shikijs/shiki/blob/v4.6.0/packages/transformers/src/transformers/meta-highlight.ts#L3-L20) · [逐行结构和 1 起算的钩子](https://github.com/shikijs/shiki/blob/v4.6.0/packages/core/src/highlight/code-to-hast.ts#L164-L216) · [空输入拆行](https://github.com/shikijs/shiki/blob/v4.6.0/packages/primitive/src/utils/strings.ts#L16-L37)
- **按需加载。** 直接 `codeToHast` 的异步简式 API 复用一个实例并按需加载，带有内嵌语法探测。本方案先收集语料使用的语言以及可识别的内嵌语法，再调用 `createHighlighter` 初始化，随后使用实例的 `codeToHast`。全包入口会把语言和主题放入异步构建分块，是否提前加载由调用参数决定。细粒度 `shiki/core` 适合固定语言集合，需显式加载主题、语言、语法依赖及正则引擎。本项目使用服务器端全包、已预览的 `github-dark-high-contrast` 主题和默认 Oniguruma 引擎。 [实例与异步简式 API](https://github.com/shikijs/shiki/blob/v4.6.0/packages/core/src/constructors/bundle-factory.ts#L160-L229) · [内嵌语法探测](https://github.com/shikijs/shiki/blob/v4.6.0/packages/core/src/utils/strings.ts#L74-L129) · [打包方式](https://shiki.style/guide/bundles) · [默认引擎](https://github.com/shikijs/shiki/blob/v4.6.0/packages/shiki/src/bundle-full.ts#L23-L30)

- **正文标题。** 直接使用 GitHub slugger，按正文 H1–H6 的 HAST 文本在每篇文档内分配唯一 slug，再统一加 `user-content-`。这是当前 `rehype-slug` 6.0.0 与净化器生成标题 ID 的规则。目录和实际标题复用同一个最终 ID。当前已发布正文含 `#user-content-使用前的检查清单`，验收应确认它仍指向唯一标题。作者用 `#标题-slug` 写同页链接，由编译器输出最终片段。已发布文章中的对应链接迁成新写法，公开目标 ID 保持有效。浏览器按标准处理 UTF-8 URL 片段编码。 [现有 slug 算法](https://github.com/rehypejs/rehype-slug/blob/6.0.0/lib/index.js#L27-L44) · [去重实现](https://github.com/Flet/github-slugger/blob/2.0.0/index.js#L19-L45) · [已发布锚点](../../content/posts/zh-CN/26-04-30.md#L12) · [浏览器片段定位](https://html.spec.whatwg.org/multipage/browsing-the-web.html#scrolling-to-a-fragment)
