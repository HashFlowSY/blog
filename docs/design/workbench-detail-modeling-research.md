# 首页工作台精细建模调研

建议把工作台重做成一套能读出装配方式和使用痕迹的实体资产。用 Blender 手工制作台钳、壳体和接头，现有 TypeScript 模型继续提供桌架尺寸、接触基准和规则件。定稿网格和同一套铅笔图集用于生成 2D 成稿和 3D 绕转帧。以 `ff04cd3` 和原始铅笔稿为基线，先做右侧台沿、台钳和显示器走线样段，确认首页尺度和放大后都能读出结构，再扩展到整件。 [原始铅笔稿](workbench-hero.png) · [现有几何与纹理统一方案](workbench-assembly-plan.md)

## 当前模型的粗糙感来自哪里

原稿里的台钳有铸件收腰、钳口和底座的体积变化，桌沿能看出厚度与接合，箱扣与提手能读出开合方式。当前正面大轮廓已校准。转到背面和底部，大面积平整面和同类排线占了画面，固定点、材料厚度和走线路径很难读出来。默认机位下 2D 与 3D 的 RGB 差值衡量两种渲染的一致性。模型精细度另看轮廓、遮挡、接合和各角度剖面。 [原始铅笔稿](workbench-hero.png) · [同机位验收记录](workbench-assembly-plan.md#验收与重新生成)

- **精度分配。** 在 Node 中读取共享几何并按顶点计数，当前有 **47,946 个三角面、586 个源表面、9 个按材质合批的运行时网格**。洞洞板占 15,286 个三角面，约 32%。主桌板所在区域共 24 个三角面，台面、台沿和底面由平面挤出形成。将新增细分用在台沿剖面、真实开口和可见轮廓上。9 个网格是模型结构计数，实际每帧提交数与帧耗时需在浏览器量。 [桌板](../../src/components/home/workbench-model.ts#L275) · [洞洞板](../../src/components/home/workbench-model.ts#L613) · [合批](../../src/components/home/workbench-model.ts#L1761) · [Three.js 渲染统计](https://threejs.org/docs/pages/WebGLRenderer.html#info)
- **已有细节的接合。** 大屏已包含背部散热装饰、插口和短线，现有短线终点在台面。台钳已分铸件、钳口和丝杆，工具箱已有扣具、提手和后铰链。优先把这些零件改成能互相咬合的形状，让遮挡、凹槽和阴影由装配关系产生。 [大屏背部与短线](../../src/components/home/workbench-model.ts#L1388) · [台钳](../../src/components/home/workbench-model.ts#L1483) · [工具箱](../../src/components/home/workbench-model.ts#L1598)

## 建模路线

1. **Blender 手工建模，离线烘焙。** 对大板边、铸件转折和塑料壳缝分别控制倒角半径、分段和边的位置。Blender 的 Bevel 可按角度或权重选择边，配合 Harden Normals 或加权法线保留大面的平整。走线可以用 Bézier 曲线控制插头出口方向、弯曲与垂度，以圆形截面生成管网格。复杂零件可以从高模烘焙法线或环境遮蔽作为绘制明暗的参考，最终把表面细节和接触暗部写入现有铅笔图集。这个办法适合边缘曲率不一、从侧背面也看得出结构的零件，代价是要维护源文件、UV 和导出过程。 [Blender Bevel](https://docs.blender.org/manual/en/4.5/modeling/modifiers/generate/bevel.html) · [Weighted Normal](https://docs.blender.org/manual/en/4.5/modeling/modifiers/normals/weighted_normal.html) · [曲线截面](https://docs.blender.org/manual/en/4.5/modeling/curves/properties/geometry.html) · [Cycles 烘焙](https://docs.blender.org/manual/en/4.5/render/cycles/baking.html)
2. **TypeScript 参数建模。** 板厚、立柱落点、孔距、键帽间距和滑轨安装面可以由共享尺寸生成。Three.js 已提供圆角盒、带倒角的截面挤出和沿曲线生成管体。现有实现已经用了这些方法，仍可通过真实截面、装配间隙和可见接触关系提高精度。代码便于维持尺寸、对称与重复关系，复杂壳体的局部形状在 Blender 中更便于对照多个视角编辑。 [现有几何构造](../../src/components/home/workbench-model.ts#L81) · [RoundedBoxGeometry](https://threejs.org/docs/pages/RoundedBoxGeometry.html) · [ExtrudeGeometry](https://threejs.org/docs/pages/ExtrudeGeometry.html) · [TubeGeometry](https://threejs.org/docs/pages/TubeGeometry.html)
3. **有尺寸的 CAD 或厂商模型。** FreeCAD 的约束草图和 CadQuery 的草图、倒圆角、装配可用于有剖面或真实尺寸的零件。可采用厂商图纸确定安装孔、板厚与行程，或从 STEP 转出展示网格后再安排 UV。CadQuery 可将装配导出为 glTF，并提供曲面离散公差。项目里先把这些资料用于台钳滑座、支架安装面等几何约束。装配图不足时，可补侧、背和底视图后再定尺寸。 [FreeCAD Sketcher](https://www.freecad.org/features.php) · [CadQuery 示例](https://cadquery.readthedocs.io/en/stable/quickstart.html) · [CadQuery STEP 与 glTF 导出](https://cadquery.readthedocs.io/en/latest/importexport.html) · [离散参数实现](https://cadquery.readthedocs.io/en/latest/_modules/cadquery/occ_impl/exporters/assembly.html#exportGLTF)
4. **生成与重建。** 单图生成适合试摆一个独立的非关键道具，或提出遮挡部位的造型草图。InstantMesh 的作者报告了薄小结构和生成视角一致性的限制。TRELLIS.2 能表达复杂表面，但作者报告了很近的平行面可能混合、偶有小孔、缺少零件级结构标注。PartCrafter 已能从单图输出多个零件，装配间距、真实孔位和原稿笔触仍需逐件验证。若能取得实物多角度照片，COLMAP 可从重叠影像恢复相机和网格，再清理拓扑和重做铅笔纹理。本文建议只在有实物时试扫有机道具，或拿生成形状做单件参考。 [InstantMesh §5](https://arxiv.org/html/2404.07191v2#S5) · [TRELLIS.2 附录 F](https://arxiv.org/html/2512.14692#A6) · [PartCrafter §4](https://arxiv.org/html/2506.05573#S4) · [COLMAP 重建与采集](https://colmap.github.io/tutorial.html#structure-from-motion)

## 接入现有的铅笔绘制流程

1. **先定部件基准。** 继续用当前相机和裁切测量原画中的桌沿、台钳落点和显示器外框。把支架和后壳、台钳底座和台面、夹具和横梁之间的连接面记到同一套坐标中。只有单张原稿时，把背部插口方向、线夹位置等记录为造型决定。右侧新增的实体从同一参考机位复投影，新增笔迹也落在对应部件上。 [参考相机](../../src/components/home/workbench-view.ts#L3) · [单视图的几何约束与补充视图](workbench-geometry-research.md)
2. **在共同的网格入口接入手工零件。** Blender 源件保留可编辑的修改器和曲线。导出副本应用修改器，把曲线转成网格，保留部件名、局部坐标、法线和 UV。glTF 或 GLB 可作交换格式。首轮可离线把少量网格整理成项目可读取的 `WorkbenchSurface`，对齐轴向、尺度和顶点绕序，保留 `region`、`finish`、`outline` 以及原稿重投影所需的信息。烘焙和浏览器从同一份归一化网格读取。若直接交付 GLB，两个入口要读取同一个导出件，用同一套无光照铅笔贴图采样，并核对展开索引、世界变换、UV 纵轴和部件归属。用 glTF Validator 检查格式，并用侧视和仰视核对实物装配。 [共享网格入口](../../src/components/home/workbench-model.ts#L81) · [Blender glTF 网格与导出选项](https://docs.blender.org/manual/en/4.5/addons/import_export/scene_gltf2.html#meshes) · [Khronos glTF 网格与属性](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#meshes) · [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html) · [glTF Validator](https://github.com/KhronosGroup/glTF-Validator)
3. **检查复杂表面的 UV 和笔迹归属。** 当前图集按非索引三角形逐面分组，多数表面按主法线轴投影并重写 UV。壳体内折、孔口和相邻曲面在同一投影中可能重叠。简单局部可沿用当前图集。若采用 Blender UV，则明确用非重叠的 UV 岛参与共同图集排布，保留岛内坐标并扩边，再由两端读取最终 UV。倒角会改变相邻面的夹角，烘焙器按 34° 阈值取边，新增过渡边和需要保留的缝线应做局部检查。新造型沿用原稿可见性与归属掩码，新添道具和原稿从未覆盖的面用补绘，防止压住旧笔迹的表面拾取原部件颜色。 [现有图集](../../src/components/home/workbench-atlas.ts#L67) · [轮廓烘焙](../../scripts/bake-workbench.mts#L454) · [原画采样](../../scripts/bake-workbench.mts#L750) · [Three.js 边线阈值](https://threejs.org/docs/pages/EdgesGeometry.html) · [Blender UV 扩边](https://docs.blender.org/manual/en/4.5/render/cycles/baking.html#margin)
4. **按同一份贴图生成三层成稿。** 几何负责钳口空隙、外壳接缝、线材和支架的真实遮挡。钳口细纹、浅划痕、木纹和擦亮面进入图集。先用固定在部件表面的接触暗部表现缝隙，再按材质安排排线。木纹沿板长，塑料靠圆角和壳缝分层，铸件的排线跟随收腰。用现有深度顺序分配工具、桌架、台面图层，更新受影响的笔画坐标与遮罩，沿用点、线、面到成稿的时序。浏览器用同一图集的颜色呈现这些笔触。 [离线同机位分层](../../scripts/bake-workbench.mts#L851) · [绘制时序](../../src/components/home/workbench-geometry.ts#L248) · [Three.js MeshBasicMaterial](https://threejs.org/docs/pages/MeshBasicMaterial.html) · [Praun 等，表面排线与缩放](https://gfx.cs.princeton.edu/proj/hatching/hatching.pdf)

## 右侧样段怎么验收

- **几何。** 参考角度看到台沿倒角与板厚，放大后能读出钳口、滑座和底座的分界。绕到右后侧能顺着显示器出线看见插头、支架附近的线夹、预留弯和桌下固定点。仰视检查台钳底座固定位置、后梁和台面之间的装配，确认插头落在端口内、线材穿过实际开口。对照原稿可见的主要锚点，单独标注有意补画或改动的轮廓。 [台钳现有装配](../../src/components/home/workbench-model.ts#L1483) · [显示器现有出线](../../src/components/home/workbench-model.ts#L1417)
- **使用痕迹。** 样段可采用一次木件试夹的场景。在钳口放一小段夹住的木件，保留旁边现有铅笔，木件棱边带少量记号，磨痕集中在钳口接触面与桌沿常接触处。用默认尺寸观察是否能读出正在做什么，再从上方看道具落点和桌面留出的操作空间。样段的道具、摆位和磨损是拟定美术方案，按样段图确认。 [桌面铅笔](../../src/components/home/workbench-model.ts#L1477)
- **2D、3D 与动作。** 在桌面和手机取景下分别比较成稿、同参考姿态的 WebGL 帧及首个实际拖动帧。检查部件遮罩和主要轮廓、恢复原位时的构图、点线面逐步揭示、新笔迹的归属和侧背面 UV 接缝。完整绕转 360°，再查看近顶、近底和最大缩放。先用灰模检查轮廓、缝和连接，再用铅笔成稿检查笔触。以同设置重测当前版本的参考帧像素差，再比较样段全图和右侧局部。 [首页绕转和触控用例](../../e2e/home.spec.ts#L140) · [同机位像素差的历史记录](workbench-assembly-plan.md#验收与重新生成)
- **浏览器成本。** 固定视口、DPR、设备、相机轨迹及缓存条件，比较静态资源传输量、2D 成稿后 3D 就绪时间、拖动时的帧间隔中位数和 95 分位，以及 `renderer.info.render` 的三角形数和绘制调用数。先测现有版和样段，再决定哪些倒角、圆弧和孔缘的细分值得保留。重复的键帽、螺钉和挂钩可共用模型。若实测绘制调用需要下降，且实例能共享几何、材质与 UV，才比较 GPU 实例化与现有按材质合批。 [Three.js 渲染统计](https://threejs.org/docs/pages/WebGLRenderer.html#info) · [W3C Resource Timing](https://www.w3.org/TR/resource-timing/) · [Three.js InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html) · [Khronos GPU 实例化说明](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Vendor/EXT_mesh_gpu_instancing/README.md#appendix-motivation-and-purpose)

样段通过后，先扩展黄抽屉、箱扣和圆凳的接合，再补笔记本、挂件和搁板。最后在整件的侧、背、俯、仰视统一检查。背面能看清线材与固定点，底部能看清桌架和柜体的承力关系，正面保留原稿构图。此方案以现有模型和源码计数为依据，样段的外观和移动端帧时间留到制作后验收。
