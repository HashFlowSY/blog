# Hashflow 首页优化方案

2026-11-18 · 首页改版候选方案。当前工作台的绘制顺序和时长见[现行绘制和交互](workbench-interaction-design.md)。

首屏给访客两条清楚的路径。第一次来的人能看到作者做什么、做过哪个项目。回来读文章的人可以直接进文章列表。工作台默认显示手绘成稿，点按插画中的部件即可操作。[首轮调研与实拍](../research/home-redesign-2026-11-18.md)

## 版式与首屏文案

桌面首段用约 5∶7 的两栏，左侧放简介和代表项目，右侧放工作台。两栏使用同一纸色。首段上下留约 60–80 px，简介与项目之间留约 32 px。画稿按栏宽自然展开。以约 900 CSS px 为试排断点，空间不足时按「简介 → 代表项目 → 工作台」改单栏。手机保留约 20 px 的左右边距，项目和画稿之间留约 32 px。工作台之后衔接有独立留白的文章区，最后是求职与合作。

## 代表项目的选择

首页从已发布项目里选一条。先在项目 Markdown 中用 `featured: true` 标记候选，再按项目填写的 `date` 从新到旧取第一条。同一天按 `slug` 正序。当前只有 `Personal Blog` 符合条件。想固定展示某个案例，只给它保留精选标记即可。没有精选案例时，设计上由「查看全部项目」链接承接。[内容目录的排序](https://github.com/HashFlowSY/blog/blob/6713edd2c4a55ab86496af9e0ad9eb6003b18f5c/src/lib/content-catalog.ts#L269) · [首页选取逻辑](https://github.com/HashFlowSY/blog/blob/6713edd2c4a55ab86496af9e0ad9eb6003b18f5c/src/app/page.tsx#L35) · [当前精选标记](../../content/projects/zh-CN/personal-blog.md#L24)

## 工作台画面

- **构图**从原稿取景，给盆栽顶部、左右桌脚和凳子留余量。桌面版可保留更多透视参考线，手机版把边缘纸面收紧，让设备可辨。用画面边缘的纸色接到页面背景，标题区保持稳定底色。黄色留给抽屉和代表项目主按钮。
- **同一幅画**用于成稿、作画和部件交互。桌面、手机各自选定取景框。同一取景框内，成稿、纸稿和部件热区按同一套原稿坐标换算。先用已有 900 × 682 成稿试排，再核对高分屏、灯罩边缘和屏幕四角。[成稿素材](../../public/assets/projects/personal-blog/workbench-finished.webp) · [原图坐标](https://github.com/HashFlowSY/blog/blob/6713edd2c4a55ab86496af9e0ad9eb6003b18f5c/src/components/home/workbench-art.ts)
- **作画节奏**沿用约 6.6 秒的过程。铅笔从右侧桌脚和台沿起笔，逐步勾出设备，最后补屏幕图纸和黄色抽屉。先检查铅笔尖与线条、局部暗部与成稿的接缝。以桌脚、屏幕框和抽屉为参照，逐帧确认交接时固定部件的位置和明暗连续。[绘制分镜](https://github.com/HashFlowSY/blog/blob/6713edd2c4a55ab86496af9e0ad9eb6003b18f5c/docs/design/workbench-interaction-design.md) · [逐笔时间表](https://github.com/HashFlowSY/blog/blob/6713edd2c4a55ab86496af9e0ad9eb6003b18f5c/src/components/home/pencil-plan.ts)

## 操作与状态

| 访客动作                 | 页面反馈                                                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 首次打开、刷新或返回     | 直接看成稿，工作灯默认亮。画上的部件随所需资源就绪而可用。                                                                                                   |
| 点桌面上的铅笔           | 成稿保持到纸稿和播放组件就绪，再在同一画幅内从头画。等待或播放时，再点画面或按 Esc 可以结束。                                                                |
| 播完、提前结束或滚出画面 | 回到完整画稿，恢复播放前的灯光状态和部件操作。键盘焦点在播放入口上时，结束后留在铅笔热区。                                                                   |
| 点画上的灯               | 灯罩、挂板和台面的暖光在原位渐变，开灯约 220 ms，关灯约 170 ms。系统开启减少动态效果时即时切换。                                                             |
| 点画上的设备或盆栽       | 外接键盘和显示器触发同一套出图，笔记本独立出图。画面上的盆栽以整株作为操作区，点按时轻摆。                                                                   |
| 开启减少动态效果         | 屏幕呈现静态图纸，叶片静止。通过画上的铅笔查看起稿、描线和成稿的静态关键帧。                                                                                 |
| 素材不可用或关闭脚本     | 简介、项目和文章链接可直接浏览。首屏成稿随初始 HTML 输出。绘制素材失败时保留成稿和可用部件，播放入口反馈失败并可重试。成稿加载失败时由替代文字交代图片内容。 |

各部件使用具名热区，在鼠标悬停或键盘聚焦时显示轮廓。窄屏的主要热区以 44 × 44 CSS px 为目标，按部件错开，点按与滑动分别识别。键盘可以用 Tab、Enter 和空格操作。显示器和外接键盘共用一个键盘入口。灯的当前状态用 `aria-pressed` 表达。[现有部件操作](https://github.com/HashFlowSY/blog/blob/6713edd2c4a55ab86496af9e0ad9eb6003b18f5c/docs/design/workbench-interaction-design.md)

## 实现与验收

1. **先排内容并验证画幅。** 首页仍从内容目录选取真实精选项目和新文章，简介、项目与文章直接输出静态 HTML。成稿用本地图像和有尺寸的 `<picture>` 呈现。没有精选项目时用项目归档承接入口，文章区域随内容更新。先在 1280 × 720 和 390 × 844 确认首屏能看到身份、项目题名和「查看项目」。完整画稿按所在列的宽度自然展开，可以延伸到首屏下方。320 px 宽、断点前后和文字放大时确认无横向溢出，项目入口仍可用。
2. **接入绘制与部件行为。** 沿用现有 SVG 分镜、灯光过渡和部件状态。进入首页先请求匹配尺寸的成稿，纸稿、铅笔和绘制组件等到点播再加载。检查点播、取消加载、快速点按、收笔、离屏、历史返回和资源失败。确认状态交接时画幅、页面和焦点稳定。用窄屏触控和桌面键盘检查热点、页面滑动和减少动画偏好。[工作台入口](https://github.com/HashFlowSY/blog/blob/6713edd2c4a55ab86496af9e0ad9eb6003b18f5c/src/components/home/assembly-workbench.tsx) · [部件状态逻辑](https://github.com/HashFlowSY/blog/blob/6713edd2c4a55ab86496af9e0ad9eb6003b18f5c/src/components/home/workbench-interactions.ts)
3. **验证静态站点。** 更新受影响的首页交互、无障碍和视觉基线。实现稳定后按仓库规则清理退役的通栏定位、自动播放和重复内容样式，再在 Chromium 与 WebKit 验证根路径与 `/blog` 产物。用相同冷缓存和节流条件比较首屏图片请求与最大内容绘制时间，并检查关闭脚本时项目、文章和成稿均可阅读。[静态产物验证](../static-verification.md)
