# Shiki 迁移功能查漏

对照范围：当前提交 `43fe480` 的两篇文章、一个项目案例、两个 Markdown 编译入口的消费者、独立于正文的页面交互、CSS、单测和静态发布验收。下文标注的是原迁移方案缺失的具体行为；决定已合入[迁移方案](spec.md)。这是迁移前的现状记录，实施结果见[验收记录](acceptance.md)。

## 验收分工

| 层级           | 新实现需要证明什么                                                                                                                                                                                                                                                                                                                                               |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 编译与内容契约 | 用新入口检查 YAML 错误的文件和行、草稿排除、结果不可变、标题与脚注 ID 唯一、净化语义、搜索分块和混排字词；显式未知语言、非法行范围和失效的同页目标使新编译失败。用合法的纯文本代码验证其显示合同。删除旧编译器、插件、估算器和旧详情组件的专门测试。现有独立内容契约和归档测试继续验证各自功能，不复制旧 DOM 断言。                                              |
| 真实发布内容   | 在静态站验证三个详情的公开片段、两个断点的回顶、窄屏术语表、推荐、项目封面与列表焦点。旧阅读选择器用例改为行为验收。WebKit 保留手机和桌面两种回顶、目录、封面；Chromium 检查键盘、无障碍和主要路径。                                                                                                                                                             |
| 隔离发布样例   | 扩充[现有隔离构建](../../e2e/fixture-independence.spec.ts#L183)：一篇文章和一个项目案例共享包含普通/缩进/空代码、跨行高亮、表格、任务项、本地图、重复脚注和混排的素材。发布样例和一个私有草稿只存在测试工作区。验证真实资源响应、文档静态 HTML、索引、卡片和详情，复制在授权的 Chromium 浏览器上下文验证实际剪贴板。已有样例调研使用过剪贴板替身，不能替代此项。 |
